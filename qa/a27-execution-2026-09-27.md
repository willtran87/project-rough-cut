## Implemented fixes

1. **Prepare image sources before play.** CPU profiles and per-call timing isolated repeated 40–60 ms stalls when a cached atlas canvas first consumed a deferred image source. Calling `image.decode()` alone did not avoid them. Managed images now prepare one reusable `ImageBitmap` during loading; atlas and horror-overlay priming waits for that source. The fallback retains normal images when the API is absent or rejects. Readiness waits for preparation, so the cost is not hidden after the game starts. Dimensions and art files are unchanged.
2. **Avoid unnecessary text repair work.** ASCII-only UI strings bypass the repeated punctuation-repair passes. Non-ASCII text retains the existing repair path. Every replacement pair and normal action text is covered by the focused regression.
3. **Give exit filing consistent instructions.** Screenshot review found “Hold still” competing with “Move quietly,” “Follow route,” “Scout the next cover” and a redundant Use prompt. Filing now owns those HUD/world-marker lines. Danger remains visible and explains movement as cancellation. During the final seal, prompts say release is authorized and no longer offer a cancellation or a basic control lesson. Both exits have causal transition tests.
4. **Check releases before upload.** The Pages workflow now runs `node tools/verify-release.mjs` before packaging the site, checking assets and scenario fixtures. This is local workflow preparation; no deployment occurred in this pass.
