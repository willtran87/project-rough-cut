# Campaign settings — recovery from temporary storage failure

The shared DOM settings panel previously applied failed writes in memory but forgot them when a later write succeeded. Reproduced through actual controls in Under the Green, Back Nine and Final Cut: change master volume to 0.25, caption size to 1.4 and Reduced Motion to enabled while storage rejects writes; restore storage, then enable Mute. Only Mute was saved. Reload discarded the earlier audio/accessibility choices despite the panel no longer reporting a persistence problem.

`web/campaign-settings-ui.js` now retains pending user-edited fields. The next settings change attempts to save those fields together, merging them into the latest stored campaign record through the existing `patchRecord` helper. A successful write clears pending fields, so a later unrelated change does not replay stale values over newer edits from another tab. Settings continue applying immediately in the current session while storage is unavailable. The existing status remains truthful; leaving before any successful retry still cannot preserve unavailable storage.

This is a campaign service fix for review items 38, 41 and 44. It does not change chapter progress, input profiles, local effect overrides or hazard rules. Level 1's existing canvas preference writer already retains failed changes; its consumers are covered by the existing campaign regression rather than being replaced.
