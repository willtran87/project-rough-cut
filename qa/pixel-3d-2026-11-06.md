# Meaningful pixel art in 3D — November 6, 2026

The default renderer now applies the original palette, material wear, foliage detail and night atmosphere to fixed three-dimensional objects. This supersedes the previous whole-illustration prop treatment. The guiding rules are in [the art direction](../design/pixel-3d-art-direction.md).

## Implementation

- Carts have actual tires, tread, seats, roof supports, steering, cargo and rear equipment. Cover uses fixed volumes derived from the existing collision footprints. Stone cover has modeled masonry courses; hedges have solid foliage volumes with irregular rims.
- Stations have separate frames and working mechanisms: bell and clapper, stamp, release lever, valve and key. Existing interaction state drives these parts. Labels attach to their frames.
- Wood, painted metal, brass, iron, stone, rubber, rust and paper use purpose-made pixel surfaces. Local leaf detail comes from original art. Object-attached triplanar coordinates and discrete perceptual shading preserve detail around curves without stretching a whole illustration onto a model.
- Trees combine trunks and layered crowns with small fixed branch components. Reeds form spatial clusters. Lamps, notice boards, floodlights, boundary posts, the shed roof and drainage arch have physical geometry.
- Local moon shadows and a nearby station lamp help explain shape. Static geometry is merged by material and spatial chunk. Dynamic mechanisms remain separate. The five-layer camera-driven parallax background is retained.
- Close-up review corrected dark texture quantization, stretched surface mapping, overly rounded tree silhouettes, inappropriate painted detail on the log paper, and the shed sign being obscured by its new roof beam.

The art pass does not edit gameplay movement, route coordinates, collision, targeting, detection or action range. Collision/line of sight still use the game's authored shapes rather than the render mesh. Joe intentionally retains directional sprite animation. Small foliage planes and distant/off-course illustrated facades also remain; this is not a claim that every element is a continuous 3D model.

## Performance and remaining evaluation

Final run on NVIDIA RTX 3090 / D3D11, Chromium 148: both treatments had 16.7 ms median frames and 16.7–16.8 ms p95 frames across all three positions, with no frames over 50 ms. The new treatment reported 276–354 draw calls and approximately 190k–229k triangles at the sampled endpoints, versus 34–64 calls and 1.4k–2.2k triangles for illustrated props. Both were approximately 60 fps in these short samples; that does not establish equivalent GPU headroom.

`tools/profile-pixel-3d.cjs` compares the previous illustrated treatment with the new default using three five-second, unrecorded requestAnimationFrame samples per mode at 1280×720. It records the actual GPU, browser, source hashes and draw statistics in `output/pixel-3d/performance/report.json`. This short desktop comparison is not sustained qualification, physical input-latency measurement or mobile hardware validation. The earlier ten-minute smooth-renderer qualification does not apply to this revision. The additional geometry and shadows increase rendering cost substantially despite static merging.

Human assessment of atmosphere, comfort and readability remains deferred as requested; use the existing prepared playtest guide. Local changes only, no deployment or commit. Compare the prior treatment with `?art=illustrated`; `?art=smooth` and `?renderer=legacy` retain the earlier alternatives.
